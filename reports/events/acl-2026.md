## 精选论文

### 1. [LongSpec: Long-Context Lossless Speculative Decoding with Efficient Drafting and Verification](https://aclanthology.org/2026.acl-long.83/)

**61/100 · LLM 高效推理 > 模型与算法效率 > 推测解码 · Long**

LongSpec 把推测解码扩展到长上下文：用恒定大小 KV Cache 的草稿模型、位置校正和混合树注意力降低长序列草拟与验证开销。

**为什么值得关注：** 它直接处理长上下文 agent 场景中“草稿模型自身也被 KV Cache 拖垮”的问题；作者报告相对 FlashAttention 基线最高 3.26× 加速。

**边界：** 性能数字来自论文指定模型与任务；服务并发、batch 和不同 GPU 上的收益仍需单独验证。

[PDF](https://aclanthology.org/2026.acl-long.83.pdf)

### 2. [UniSpec: Training-Free Speculative Decoding for Robust LLM Acceleration Across Languages and Hardware](https://aclanthology.org/2026.acl-long.285/)

**59/100 · LLM 高效推理 > 模型与算法效率 > 推测解码 · Long**

UniSpec 通过设备校准、候选置信度和树扩展策略，提供无需训练、跨语言和跨硬件的无损推测解码。

**为什么值得关注：** 无需训练和设备感知降低了部署门槛；作者在多语言、多模型和多硬件上报告最高 2.6× 加速，并公开代码与 benchmark。

**边界：** 训练免费不等于运维免费，首次设备校准和 workload 漂移下的稳定性仍需测量。

[PDF](https://aclanthology.org/2026.acl-long.285.pdf)

### 3. [SpecCache: Speculative KV Cache Reuse for Efficient RAG Serving](https://aclanthology.org/2026.acl-long.859/)

**53/100 · LLM 高效推理 > Runtime 与内存效率 > Attention 与 KV Cache · Long**

SpecCache 用轻量 speculative model 的深层特征预测 RAG 中需重算的关键 token，以较低成本提高 KV Cache 复用质量。

**为什么值得关注：** 直接优化 RAG 长上下文的 TTFT；作者报告 TTFT 降低 2.17–3.95×、吞吐提升 2.7–5.2×，工程信号很强。

**边界：** 摘要级证据尚不足以判断索引更新、不同检索语料及多租户并发下的收益。

[PDF](https://aclanthology.org/2026.acl-long.859.pdf)

### 4. [OjaKV: Context-Aware Online Low-Rank KV Cache Compression](https://aclanthology.org/2026.findings-acl.494/)

**53/100 · LLM 高效推理 > Runtime 与内存效率 > Attention 与 KV Cache · Findings**

OjaKV 以在线 PCA 更新低秩 KV 子空间，并保留少量全秩 anchor，使长上下文压缩能适应分布变化。

**为什么值得关注：** 它兼容 FlashAttention，并把静态低秩压缩改成 prefill/decode 在线适配，适合变化较大的长上下文流量。

**边界：** 属于 Findings；在线子空间更新的实际 GPU 开销和高并发下的状态管理需要复核。

[PDF](https://aclanthology.org/2026.findings-acl.494.pdf)

### 5. [OCP: Outlier-Centric Probing for Dynamic Structured Pruning of LLMs](https://aclanthology.org/2026.acl-long.276/)

**52/100 · LLM 高效推理 > 模型与算法效率 > 压缩、稀疏与蒸馏 · Long**

OCP 用 outlier 敏感度、注意力信号和分层动态稀疏率改进输入自适应结构化剪枝。

**为什么值得关注：** 方法强调硬件友好结构，并报告在 Llama/OPT 上以 1.6× 加速获得更低 perplexity。

**边界：** 在线 probe 与动态稀疏控制会引入额外开销，需核对端到端 latency 而非仅模型计算量。

[PDF](https://aclanthology.org/2026.acl-long.276.pdf)

### 6. [PDTrim: Targeted Pruning for Prefill-Decode Disaggregation in Inference](https://aclanthology.org/2026.acl-long.1842/)

**52/100 · LLM 高效推理 > Serving 与分布式推理 > Prefill-Decode 解耦 · Long**

PDTrim 根据 prefill 与 decode 的不同敏感性选择可删 block，把结构化剪枝与 Prefill-Decode 解耦部署联合优化。

**为什么值得关注：** 论文把模型压缩决策与实际 serving 架构结合，提示两个阶段不应使用同一剪枝方案。

**边界：** 摘要未提供足够的硬件、吞吐和精度权衡数字，暂不应直接外推到生产集群。

[PDF](https://aclanthology.org/2026.acl-long.1842.pdf)

### 7. [Theory-optimal Quantization Based on Flatness](https://aclanthology.org/2026.acl-long.1767/)

**50/100 · LLM 高效推理 > 模型与算法效率 > 量化与低精度 · Long**

BDQ 从 outlier 的 Flatness 指标推导双向对角变换，改善 LLM 的 W4A4 与更低比特后训练量化。

**为什么值得关注：** 作者报告 Llama-3-8B W4A4 精度下降低于 1%，并覆盖 70B reasoning 模型，具备部署相关性。

**边界：** 精度结果不能替代真实 kernel 加速；需确认具体硬件是否具有匹配的低比特算子。

[PDF](https://aclanthology.org/2026.acl-long.1767.pdf)

### 8. [EQUIP: EQUivariant preserving In-Place updates for Efficient Token Pruning](https://aclanthology.org/2026.acl-long.1210/)

**49/100 · LLM 高效推理 > 模型与算法效率 > 压缩、稀疏与蒸馏 · Long**

EQUIP 将 token 淘汰与后续插入合并为 KV Cache 原地替换，并缓存 RoPE 计算，减少 pruning 后的搬移与重算。

**为什么值得关注：** 它关注多数 pruning 论文忽略的数据移动成本，并给出 CPU/GPU 与 PagedAttention 组合的端到端速度数据。

**边界：** 需要在常见 vLLM/SGLang 工作负载与不同页大小下复现实装收益。

[PDF](https://aclanthology.org/2026.acl-long.1210.pdf)

### 9. [Prune as You Generate: Online Rollout Pruning for Faster and Better RLVR](https://aclanthology.org/2026.acl-long.632/)

**48/100 · AI 基础设施 > 训练与数据中心基础设施 > 分布式训练与 Checkpoint · Long**

ARRoL 在 RLVR 生成过程中预测部分 rollout 的成功率，提前剪枝并重新组 batch，减少无效采样和训练计算。

**为什么值得关注：** 它把 rollout 选择嵌入 inference engine；作者在 Qwen/Llama 训练上报告最高 1.7× 加速且平均准确率上升。

**边界：** 质量头的泛化、错误早停偏差和分布式训练通信占比需要更完整复现。

[PDF](https://aclanthology.org/2026.acl-long.632.pdf)
