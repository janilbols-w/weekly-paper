## 一分钟结论

OSDI 2026 已公开 136 篇正式论文。本届与 LLM 高效推理和 AI Infra 直接相关的内容不再只是零散论文，而是形成了 KV Cache 与长上下文、资源高效推理、超大规模训练、MoE 通信、GPU 可靠性和异构集群调度等完整议程簇。

最强工程信号来自生产规模：SGLang 与多级 KV Cache、万卡级 Qwen MoE 训练、35M GPU-hours 的静默错误检测、10K+ GPU 的多模型显存共享，以及 155,410 GPU 的异构集群追踪。报告保留论文作者的条件化性能结论，不把跨硬件、跨模型的峰值数字直接视为普适收益。

## 精选论文

### 1. [ADAngel: Accelerating Arbitrary-Precision Quantized LLMs with Adaptive Computing Mapping](https://www.usenix.org/conference/osdi26/presentation/liu-yao)

**55/100 · LLM 高效推理 > 模型与算法效率 > 量化与低精度 · Resource-Efficient LLM Serving**

ADAngel 用 DPR 模型系统生成多种 mixed-precision GEMM 策略，再针对目标模型离线穷举形成 Oracle Policy Map，由轻量 dispatcher 为运行时不同 shape/bit-width 选择 kernel。

**为什么值得关注：** 它处理 W4A8 等 arbitrary-precision 推理中“静态 kernel 无法覆盖形状与位宽异质性”的问题；作者报告 decode 相对 llama.cpp 最高 5.10×，prefill TTFT 相对 TensorRT-LLM 提升 1.17×–2.38×。

**边界：** 需要为目标模型和硬件做离线穷举与专用策略集；收益不能脱离具体 bit-width、shape、GPU/edge 平台与基线版本解释。

[PDF](https://www.usenix.org/system/files/osdi26-liu-yao.pdf)

### 2. [Strata: Hierarchical Context Caching for Long Context Language Model Serving](https://www.usenix.org/conference/osdi26/presentation/xie-zhiqiang)

**53/100 · LLM 高效推理 > Runtime 与内存效率 > Attention 与 KV Cache · KV Cache and Long Context**

Strata 把长上下文 KV Cache 的 GPU HBM、CPU 内存和 SSD 多级缓存作为统一系统处理，用 GPU-assisted I/O 合并碎片化小传输，并让调度器显式感知缓存加载时延与 delay hit。

**为什么值得关注：** 它已集成 SGLang 并进入生产；作者在指定长上下文模型和工作负载上报告吞吐最高为 vLLM-LMCache 的 5×、TensorRT-LLM 的 3.75×，同时保持短上下文性能。

**边界：** GPU-assisted I/O 会占用少量 SM；收益依赖缓存命中、页布局、CPU-GPU 互联和长上下文比例，峰值加速不能直接外推到任意在线流量。

[PDF](https://www.usenix.org/system/files/osdi26-xie-zhiqiang.pdf)

### 3. [Tessera: A Holistic Pipeline Parallelism Framework for Trillion-Parameter Heterogeneous MoE Training (Operational Systems)](https://www.usenix.org/conference/osdi26/presentation/hu-weifang)

**53/100 · AI 基础设施 > 训练与数据中心基础设施 > 分布式训练与 Checkpoint · LLM Training at Scale · Operational Systems**

Tessera 面向异构 MoE/attention block 的超大模型训练，联合优化 pipeline partition 与 compute-communication overlap，并在运行时用 dynamic bubble optimizer 填补 MoE 路由造成的瞬时空洞。

**为什么值得关注：** 系统用于 Qwen3 与 Qwen3-Next 生产预训练；在 4,096–12,288 GPU 的五个工作负载上，作者报告吞吐提升 20%–33%，万亿参数模型达到 39% MFU。

**边界：** 主要证据来自阿里生产栈和特定 Qwen 异构结构；与 Megatron-Core 的公开对照规模和生产基线并不完全相同，迁移到其他模型/互联需重新 profile。

[PDF](https://www.usenix.org/system/files/osdi26-hu-weifang.pdf)

### 4. [StriaTrace: Efficient Tracing and Diagnosis for Online LLM Inference (Operational Systems)](https://www.usenix.org/conference/osdi26/presentation/wu-haonan)

**53/100 · AI 基础设施 > 服务平台 > 可观测性与 Benchmark · Agentic AI and LLM Operations · Operational Systems**

StriaTrace 只持续跟踪关键同步点和 critical path，在异常时再加深 tracing，并用动态回归 roofline 与相关性诊断定位在线 LLM 推理的偶发 SLO 抖动。

**为什么值得关注：** 系统已用于开发、测试和生产发布，覆盖 19 类根因；论文报告相对替代方案 tracing 开销降低 97.8%，完整方案约 1% 级开销。

**边界：** 设计针对特定线上 inference stack 的同步边界与根因库；跨 serving engine、异步执行图和新硬件时需要重新定义 instrumentation 与诊断模型。

[PDF](https://www.usenix.org/system/files/osdi26-wu-haonan.pdf)

### 5. [Prism: Cost-Efficient Multi-LLM Serving via GPU Memory Ballooning](https://www.usenix.org/conference/osdi26/presentation/yu-shan)

**52/100 · LLM 高效推理 > Runtime 与内存效率 > 缓存、换入换出与内存管理 · KV Cache and Long Context**

Prism 用 GPU memory ballooning 在多模型之间统一空间共享和时间共享；其 kvcached 驱动作为 inference engine 与 GPU 内存之间的 shim，按流量变化回收和重新分配显存。

**为什么值得关注：** kvcached 已开源并部署到 10K+ GPU；论文报告在同等 GPU 数下 SLO 达标率显著提升，在同等 SLO 下成本最高降低超过 2×。

**边界：** 核心假设是生产流量存在动态 bursty-group；接入需要 engine/runtime 与显存回收语义配合，隔离、抖动和不同模型内存布局下的收益需实测。

[PDF](https://www.usenix.org/system/files/osdi26-yu-shan.pdf) · [代码](https://github.com/ovg-project/kvcached)

### 6. [Efficient LLM Serving on Commodity GPU Clusters with Data-Reduced Cross-Instance Orchestration](https://www.usenix.org/conference/osdi26/presentation/du)

**52/100 · LLM 高效推理 > Serving 与分布式推理 > Prefill-Decode 解耦 · Resource-Efficient LLM Serving**

EcoServe 为缺少高速互联的 commodity GPU 集群设计 partially disaggregated serving：单实例内按时间解耦 prefill/decode，再让多个实例循环协作，并配合自适应路由与细粒度扩缩容。

**为什么值得关注：** 在 32 张 L20、Ethernet 互联、30B/70B 模型上，作者报告 goodput 相对 vLLM、Sarathi、DistServe、MoonCake 提升 1.96×–2.51×，代码已公开。

**边界：** 最大收益来自 L20+Ethernet 的带宽约束场景；在 H100+NVLink+InfiniBand 上只称“保持竞争力”，不同网络与模型下应重新比较 NoDG/FuDG 成本。

[PDF](https://www.usenix.org/system/files/osdi26-du.pdf) · [代码](https://github.com/MLSysU/EcoServe)

### 7. [Murakkab: Resource-Efficient Agentic Workflow Orchestration in Cloud Platforms](https://www.usenix.org/conference/osdi26/presentation/chaudhry)

**51/100 · AI 基础设施 > 服务平台 > Gateway、路由与弹性 · Agentic AI and LLM Operations**

Murakkab 用声明式 agent workflow 抽象解耦逻辑、模型和硬件，再以 profile-guided optimizer 与 adaptive runtime 跨层选择模型、硬件和执行配置。

**为什么值得关注：** 对 agent 系统而言，单次 model call 优化不够；作者在多类 workflow 上报告 GPU 用量最高降低 2.8×、能耗 3.7×、成本 4.3×，同时满足 SLO。

**边界：** 收益依赖 workflow 可声明、可 profile，且需要把质量约束转化为优化器可用目标；工具调用延迟、模型漂移和未见过的 workflow 可能削弱离线 profile。

[PDF](https://www.usenix.org/system/files/osdi26-chaudhry.pdf)

### 8. [No Buffer, No Bottleneck: Efficient Zero-Copy KV Cache Offloading for Long-Context LLMs](https://www.usenix.org/conference/osdi26/presentation/luo)

**48/100 · LLM 高效推理 > Runtime 与内存效率 > Attention 与 KV Cache · KV Cache and Long Context**

DirectKV 面向 Grace Hopper/Blackwell 类 CPU-GPU 一致互联平台，让 GPU kernel 直接访问 CPU-resident KV Cache，取消 GPU staging buffer，并用融合与流水隐藏 CPU 内存访问。

**为什么值得关注：** 在 GH200 上，作者报告 CPU-GPU 传输量最高减少 50%、GPU 内存占用降低 43%、端到端性能最高提升 1.2×，直接对应长上下文容量与带宽瓶颈。

**边界：** 目前主要是节点内优化；跨节点 context parallel、多级存储层和 host-memory pressure 仍需额外 runtime 支持，退化到 pageable 或磁盘层后 zero-copy 优势会减弱。

[PDF](https://www.usenix.org/system/files/osdi26-luo.pdf)

### 9. [Simple Is Better: Multiplication May Be All You Need for LLM Request Scheduling](https://www.usenix.org/conference/osdi26/presentation/zhang-dingyan)

**47/100 · LLM 高效推理 > Serving 与分布式推理 > Batching 与请求调度 · KV Cache and Long Context**

LMetric 用“新 prefill token 数 × 当前 batch size”这一乘法分数同时表达 KV Cache 亲和性与负载均衡，避免线性组合的 workload-specific 调参和模拟器依赖。

**为什么值得关注：** 作者在聊天与 coding-agent 生产流量上报告，相对 vLLM-v1 和生产调度器，TTFT 分别最高降低 92% 和 39%，TPOT 最高降低 24% 和 51%，并已 canary 部署。

**边界：** 结果依赖论文选择的两个指标、模型和 trace；作者虽给出乘法失效条件与检测方法，但跨引擎、跨缓存策略和强突发流量仍需复现。

[PDF](https://www.usenix.org/system/files/osdi26-zhang-dingyan.pdf)

### 10. [Teaching the Old Dog New Tricks: Building Efficient Data Pipelines for Large-Scale LLM Pre-Training (Operational Systems)](https://www.usenix.org/conference/osdi26/presentation/chen-luofan)

**47/100 · AI 基础设施 > 训练与数据中心基础设施 > 数据管线 · LLM Training at Scale · Operational Systems · Jay Lepreau Best Paper Award**

这篇 Best Paper 从大规模预训练生产 trace 提炼出跨数据中心 checkpoint、启动加载 I/O 风暴和多模态数据变换三个瓶颈，并分别采用预测复制、hot-file 预复制与存储侧 CPU offload。

**为什么值得关注：** 作者报告单次评估浪费的 GPU-hours 从 16,800 降至 4,000、启动 checkpoint 加载缩短 40.8%、dataloading stall 降低 63.2%，说明“旧存储系统”可通过接口协同获得高回报。

**边界：** 方案依赖训练框架提前暴露 world size、文件热度和访问计划；生产数字来自特定存储拓扑与训练流程，复制成本和跨团队改造量需单独核算。

[PDF](https://www.usenix.org/system/files/osdi26-chen-luofan.pdf)

### 11. [SDCs in the Wild: Characterizing and Diagnosing SDC-Defective GPUs in Production LLM Training (Operational Systems)](https://www.usenix.org/conference/osdi26/presentation/zheng)

**46/100 · AI 基础设施 > 训练与数据中心基础设施 > 容错与弹性 · Training Reliability and Silent Errors · Operational Systems**

SDCs in the Wild 分析 23 块生产集群中的 SDC-defective GPU，发现老化、数据依赖和功能单元依赖会让设备通过常规压力测试却在真实训练输入上出错，并提出基于触发工作负载 replay 的 SDCHunter。

**为什么值得关注：** 作者称标准行业测试漏掉超过 60% 的缺陷设备；SDCHunter 在 ByteDance 生产环境处理了 40 起 SDC 事件，为大模型集群验收和故障隔离提供了更贴近 workload 的路径。

**边界：** 样本只有 23 块缺陷 GPU，来自单一生产环境；replay 依赖保留触发输入与执行条件，不能替代通用硬件健康检查，也未证明对所有 GPU 代际同样有效。

[PDF](https://www.usenix.org/system/files/osdi26-zheng.pdf)

### 12. [Heterogeneity at Hyperscale: Characterization and Scheduling of Large Production AI Clusters at Alibaba (Operational Systems)](https://www.usenix.org/conference/osdi26/presentation/li-suyi)

**45/100 · AI 基础设施 > 集群与资源系统 > GPU 调度与虚拟化 · Fleet and Cluster Scheduling · Operational Systems**

论文发布阿里 ASI 六个月、155,410 张多厂商多代 GPU 的生产 trace，指出不可分配空闲主要来自跨节点碎片、CPU 配比、网络 locality 与安全余量，而非 fractional-GPU 碎片。

**为什么值得关注：** 部署的 defragmentation 使有空闲资源的节点数下降 20.2%，SpotGPU 将 GPU allocation ratio 从 68% 提升到 93%；公开 trace 也为异构调度研究提供罕见基线。

**边界：** trace 不含专用集群上的大规模 foundation-model 预训练，job subtype 粒度较粗，且论文主要聚焦 GPU；结论不应直接代表所有训练集群。

[PDF](https://www.usenix.org/system/files/osdi26-li-suyi.pdf)
